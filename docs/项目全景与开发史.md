## 一、项目是什么

**Neutronstar（neutronstar.fun）**：个人全栈博客。目标形态三件套：

```
浏览器
  ├─ https://neutronstar.fun      → Cloudflare Worker「neutronstar-web」(SSR)
  │                                 源码 = web/（Astro 7 + Svelte 5 + React 19 islands）
  │                                 外壳 1:1 复刻开源主题 Shirone，数据全部来自后端 API
  ├─ https://bff.neutronstar.fun  → Cloudflare Worker「kirameku-bff」
  │                                 源码 = worker-bff/（Hono：边缘缓存/聚合/SSE 实时/Durable Object）
  └─ https://kirameku-api.neutronstar.fun → Cloudflare Tunnel → NAS(192.168.5.4) Docker
                                    ├─ kirameku-backend :8100→8000（FastAPI + SQLModel + PG16
                                    │   + /admin Vue 管理后台 + /uploads 图片）
                                    └─ kirameku-pg :15432→5432（PostgreSQL，库名 kirameku）
```

三个仓库：外仓 `Kirameku2.0`（后端+BFF+docs，master）、前端子仓 `web/`（独立 git，main，**外仓看不见它的改动**）、图床仓 `fastimage`。

## 五、踩坑精华（完整版见 [`docs/坑大全.md`](坑大全.md)，共 40+ 条）

**十条最致命的，违反任何一条都会翻车：**

1. **island 在 SSR 期 return null = 整页截断且 200 照常**（坑 6.1.14）——潜伏多日无人发现。
2. **NAS 的 `kirameku-pg` 容器与两个数据卷绝不碰**；重建只动 `kirameku-backend`。
3. **`web/` 是独立 git 仓**，外仓看不见它的改动；两仓各自 add/commit/push。
4. **不要 `git add -A`**（历史教训：把 WIP 一起打包）；一律显式路径。
5. **改后端必须 SMB 同步 → docker build → 重建容器**，只 restart 不生效（镜像落后于源码的真实事故）；有模型变更先跑 Alembic 迁移再启动（否则 create_all 撞表）。
6. **admin/dist 同步后必须 restart 后端容器**（robocopy /MIR 重建目录改变 inode，bind mount 失效 → /admin 全 404，坑 6.3.18）。
7. **cloudflared 必须 `--protocol http2`**（NAS 网络禁 UDP/QUIC，默认协议注册后立即超时）。
8. **B 站 API 风控矩阵**（坑 6.3.19）：浏览器直连 403、CF Worker 出口 412、`ps>20` 返回 -400；唯一可行 = NAS 后端代拉 + 翻页聚合 + 边缘缓存；B 站图片 CDN 防盗链 → `referrerPolicy="no-referrer"`。
9. **Astro 7 `astro dev` 本机不可用**（工具链 bug），验证一律 build+preview 或 wrangler dev；SSR 错误在 preview 里被吞，用 `wrangler dev` 看堆栈（坑 6.1.15）。
10. **BFF 代理 fetch 必须 `redirect:"manual"`**，否则后端 302 被吃掉（OAuth 断链）。

## 七、二次开发须知（30 秒版）

**三条铁律**：① 不碰 PG 容器与数据卷；② 不 `git add -A`；③ 密钥/`.env` 绝不入库。

**部署链路**（详情看 `docs/命令与运维速查.md` 第 8 节）：

| 改什么 | 部署方式 |
|:--|:--|
| `web/` 前端 | push main → CI 自动部署（约 1.5 分钟） |
| `worker-bff/` | `pnpm exec wrangler deploy`（凭据在 `.cf.local.env`） |
| `Kirameku-backend/` 后端 | SMB 同步 → NAS build → `rebuild-backend.sh` 重建容器 |
| `admin/` 后台界面 | 分步 build → robocopy dist → **必须 restart 后端容器** |

**改前必读**：对应分区坑（`docs/坑大全.md`）+ 涉及组件文件头注释（本仓库代码注释密度很高，文件头即说明书）。

**验证清单**：13 个路由 200 + BFF/后端 health + admin 200 + www 301（完整清单见 `docs/命令与运维速查.md` 8.5）；**SSR 页面改动必须验证响应完整性**（footer 出现次数，不能用 `</html>` 判断——Astro 产物本就不输出它）。
