# NeutronStar / Kirameku2.0 开发过程、踩坑与二次开发指南

> 更新时间：2026-09-09  
> 目标：记录本次从旧 Vite/React SPA 切换到 Astro + Worker BFF + FastAPI 的完整过程，方便后续维护和二次开发。

## 1. 最终架构

```text
浏览器
  │
  ├─ neutronstar.fun
  │    └─ Cloudflare Pages：Astro 静态主站
  │
  ├─ bff.neutronstar.fun
  │    └─ Cloudflare Worker：Hono BFF、缓存、图片代理、失效
  │
  └─ kirameku-api.neutronstar.fun
       └─ Cloudflare Tunnel → NAS Docker → FastAPI
                                      │
                                      └─ PostgreSQL
```

## 2. Shirone 视觉复刻实现

### 2.1 首页

首页由以下层组成：

1. `SiteHeader.astro`：毛玻璃顶栏和后台导航；
2. `HomeHero.astro`：全屏 Hero、遮罩、介绍面板；
3. `AlbumCarousel.tsx`：直接使用相册图片链接自动轮播；
4. `Sidebar.astro`：作者、导航、公告、分类、标签、日历；
5. `HomeFeed.tsx`：文章和说说实时数据。

关键样式集中在：

```text
web/src/styles/global.css
web/src/styles/animations.css
```

不要在组件内新增随机颜色。优先增加 M3 语义变量，再使用：

```text
bg-surface
bg-surface-container
text-on-surface
text-on-surface-variant
text-primary
```

### 2.2 相册轮播

当前轮播数据来源：

```text
web/src/data/albums.ts
```

每个相册取前两张图片，自动组成首页轮播。图片仍然是原相册 URL，不复制数据库数据，也不新增首页专用图片表。

后续如果后端 `/api/albums` 数据完整，只需要把 `AlbumCarousel.tsx` 中的静态 `albums` 换成 `useAlbums()`，页面结构不需要改动。

### 2.3 侧边栏开关

后台配置键：

```text
sidebar_widgets
```

配置格式：

```json
{
  "author": true,
  "explore": true,
  "announcement": true,
  "categories": true,
  "tags": true,
  "calendar": true
}
```

前端节点通过 `data-sidebar-widget` 标记，`SidebarVisibility.tsx` 拉取配置后设置 `hidden`。因此：

- 不需要重新构建前端；
- 管理后台修改后下一次加载即可生效；
- 配置接口由 BFF 缓存，正常情况下几十秒内刷新；
- 未配置时使用全开默认值，避免后台配置缺失导致侧栏消失。

## 5. 本次遇到的关键坑

### 5.1 Windows 下 `NODE_OPTIONS=...` 不是 PowerShell 语法

错误：

```bash
NODE_OPTIONS=--max-old-space-size=8192 vite build
```

PowerShell 正确写法：

```powershell
$env:NODE_OPTIONS="--max-old-space-size=8192"
pnpm exec vite build
```

### 5.2 Astro 布尔属性不能依赖猜测

首页曾经传入 `home`，但构建产物没有渲染 Hero。最终改成在布局内同时判断：

```ts
const isHome = home || Astro.url.pathname === "/";
```

这样即使调用方属性被改变，根路径仍然稳定进入首页布局。

### 5.3 Cloudflare Pages 部署目录

本项目使用：

```text
dist/client
```

不要误传 `dist` 或 `dist/server`。`dist/server/wrangler.json` 可能提示缺少 `pages_build_output_dir`，当前命令显式传入目录即可。

### 5.4 旧 Pages 项目会占用自定义域名

绑定 `neutronstar.fun` 失败时，需要先：

1. 查询所有 Pages 项目；
2. 查找旧项目拥有的 custom domains；
3. 删除旧项目的自定义域名；
4. 删除旧项目；
5. 将 DNS CNAME 切到新 Pages 项目；
6. 给新项目重新绑定根域和 `www`。

不能直接删除有 custom domain 的旧项目。

### 5.5 `www` 不能只依赖 Pages 同站点

需求是 `www` 统一跳转到根域，因此额外创建了 Cloudflare Dynamic Redirect Rule：

```text
http.host eq "www.neutronstar.fun"
→ https://neutronstar.fun + 原路径
```

### 5.6 BFF 可能缓存旧的 404

新增配置接口后，如果 BFF 仍返回旧的 404，需要使用查询参数进行验证：

```text
/api/site-config/sidebar_widgets?verify=时间戳
```

正式页面仍然使用无参数 URL，不需要修改业务代码。

### 5.7 NAS Docker 重建不能破坏数据

重建 FastAPI 容器时必须保留：

- `kirameku_uploads` volume；
- PostgreSQL 容器；
- `DATABASE_URL`；
- `SECRET_KEY`；
- CORS；
- `admin/dist` 挂载。

只删除并重建应用容器，不删除 PostgreSQL 数据卷。

## 6. 二次开发约定

### 6.1 数据

- 展示内容必须走 HTTP API；
- 不要在页面组件里写死文章、说说、友链；
- UI 默认值可以存在，但必须有 API 失败兜底；
- 修改数据库模型必须使用 Alembic。

### 6.2 页面

- 页面容器统一使用 `Page.astro`；
- 可交互区域使用 React island；
- 不要把重型交互全部放入 Astro 静态模板；
- 新增视觉变量写入 `global.css`；
- 新动画必须支持 `prefers-reduced-motion`。

### 6.3 注释

新增组件至少说明：

1. 数据来源；
2. 水合时机；
3. 关键动画参数；
4. 后续替换数据源的方法。

本次重点组件已补充中文注释：

- `HomeHero.astro`
- `AlbumCarousel.tsx`
- `SidebarVisibility.tsx`
- `MobileNavigation.tsx`
- `site_config_service.py`
