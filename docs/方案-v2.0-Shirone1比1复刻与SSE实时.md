## 1. 首页没做到 1:1 的根因（已逐文件核实）

1. **上游基线是残卷**：旧 `_upstream_shirone/` 只抓了 `src/components`+assets，缺 pages/layouts/styles/config/constants/utils/i18n/plugins/integration 共 8 个总装目录。
2. **首页结构被自创件替代**：Shirone 真实首页 = `[...page].astro → MainGridLayout(page=home) → Layout + TopAppBar + BannerStage + SideBar + CategoryBar + PostPage + Pagination`；旧实现自创了 HomeHero（相册背景+SCROLL 提示+intro 卡），原版不存在。
3. **视觉系统缺失**：原版 `main.css + variables.styl + font-faces.css + textures.css`、M3 动态色相（--hue）、四套字体角色、Swup 过渡均未移植，只有 424 行手写 global.css。
4. **生态差异**：Shirone 是 Astro+Svelte5 混合，旧工程用 React 重写交互，细节持续丢失。

**修复总原则：整体移植外壳，只换数据血。**

## 2. 目标架构（三层 + SSE 实时回路）

```
浏览器（Astro 静态壳 + Svelte 组件 + React 动画 islands + EventSource）
   │ HTTPS
边缘层 Cloudflare Workers（Hono）：/bff 聚合 · /api 缓存代理 · /img 图片优化
   │                              KV tag 索引 · ★ RealtimeRoom Durable Object（SSE 扇出）
   │ 未命中回源（Cloudflare Tunnel）
源站 NAS Docker：FastAPI :8100 + PostgreSQL 15432 + Vue Admin + uploads
```

实时回路（方案 A）：

1. 后台写库（文章/说说/相册/评论/导航配置）；
2. FastAPI service 层发领域事件 → POST BFF `/internal/revalidate`（HMAC）：
   - 一路按 cache-tag 从 KV 取 URL，`caches.delete` 精确清边缘缓存 + 预热；
   - 一路把 `{channel, type, id, action}` 投递给 **RealtimeRoom DO**；
3. DO 维护各频道（home/posts/moments/albums/comments/nav…）的 SSE 连接集合，向在线浏览器扇出；
4. 前端 EventSource 收到事件 → SWR `mutate` 对应接口 → 新内容以 Kirameku 入场动画插入；导航/主题配置事件即时刷菜单与设置。

DO 免费额度对个人站足够；SSE 走 BFF 同源，浏览器不直连 NAS。

## 4. 1:1 移植工作法

1. 上游完整基线已就位：`_upstream_shirone/`（pinned `b79d301`，由 `scripts/sync-upstream.mjs` 管理，不入库）。
2. **外壳层直接移植**：Layout.astro / MainGridLayout.astro / styles / constants / utils / i18n / config / plugins / integration 原样搬入 `web/`，路径别名对齐原版（@components、@/config 等）。
3. **数据层换血**（唯一允许偏离原版的地方）：
   - 原版 content collection（本地 md / 同步脚本）→ BFF API；
   - `getSortedPosts()` → `/bff/archive`、`/bff/home`；
   - SideBar 的分类/标签/统计/日历 → 对应 API（缺的后端补）；
   - profile/site/banner/导航配置 → 后端 site_config（后台可改）。
4. **组件保留策略**：原版 .svelte 全部保留直接挂；仅说说 MomentSection、相册 AlbumSection/AlbumGallery、友链 FriendSection 三个区块的**内部呈现**替换为 React islands（Kirameku 动画），外壳（标题、页头、间距）仍用原版。
5. **拆除清单**：HomeHero.astro、AlbumCarousel.tsx、手写 Base/Page/SiteHeader/Sidebar/AuthorCard/Calendar/SurfaceCard/PageHeader/SiteFooter、global.css/animations.css、`src/data/albums.ts`（234 张演示图先导入后端再删）。
6. **逐页像素走查**：官方演示站截图 vs pages.dev 预览截图，桌面/移动 × 亮/暗四组，不过不验收。

## 5. 动画规格（Kirameku，React islands）

- **说说**：按日分组；同日堆叠 top 递增 18px、zIndex 倒序；确定性倾斜序列 [-2,1.5,-1,2,-1.5,1,-0.5,1.5]；点击 spring(300,25) 归正展开；stagger 入场；评论楼中楼拍平 + AnimatePresence 高度折叠；SSE 新说说从顶部弹入。
- **相册**：CSS columns 真瀑布流；拍立得白边胶带；旋转角由 photo.id 确定性派生；灯箱 spring + 键盘/触摸（按需 dynamic import）。
- **友链**：相册式错位卡片，分类筛选、悬浮展开、键盘可达。
- 全局：统一 variants.ts；`prefers-reduced-motion` 降级；移动端关重特效；禁止渲染期随机。

## 6. 互动：GitHub OAuth 评论 + 持久点赞

## 10. 风险

1. Svelte+React 双框架：islands 按需水合，注意样式作用域冲突，统一由 Tailwind 4 + 原版 stylus token 约束。
2. Workers 兼容性：mermaid 等重客户端库动态加载；构建期脚本只在本地/Pages 构建跑。
3. DO 长连数量：个人站量级无忧；SSE 断线自动重连 + SWR 兜底，DO 挂了也只是退化为轮询。
4. 上游升级：pinned SHA 锁定，升级走 sync 脚本 + 像素回归，不追新。
5. SEO：内容页 SSR 出 HTML，SSE 只做增量不替代首屏数据。
