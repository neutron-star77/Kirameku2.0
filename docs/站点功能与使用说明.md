## 3. 各页面内容从哪来 & "内容不见了"的真相

### 3.1 数据链路一句话

> **前台页面本身只是"壳"，所有文章/说说/相册/友链/评论内容都存在 NAS 的 PostgreSQL 数据库里**，通过 后台(admin) 或 API 增删改。前台每次打开页面实时从数据库取数（中间有最长 60 秒的边缘缓存）。

### 3.3 直接回答："为什么文章页没有之前的文章？"

**不是"改了没推送"**——两个代码仓都已推送且部署成功（前端 CI 全绿）。真实原因有三层：

1. **新站初期只导入了 8 篇文章**。新站上线时做过"数据换血"：旧站内容默认不带过来。**2026-09-13 已补齐迁移**：从旧仓 HewllBlog（Next.js 代）找回缺失的《洛神赋》《千字文》《难经》3 篇导入，并核对了更早的 Typecho 库（NAS MariaDB `typecho1.3`）——其 5 篇文章与新站完全重合（部分在后来的博客里改过标题：《0-JpgLossless》→《图片压缩》、《13》→《革命》、《17》→《大远征》），**至此三代博客（Typecho → HewllBlog → Astro）的全部正式文章都已在站**。Astro 旧仓里剩下的 hello-astro / launch-day / guide 等是主题自带示例文，不算你的内容，未迁移。
2. **旧博客域名已下线**：`blog.neutronstar.fun` 的 DNS 已注销打不开，但那是展示问题，数据层面文章都已迁齐。
3. **09-13 之前，页面本身还有个 bug 会"吃掉"内容**：首页/归档/文章页的 HTML 被随机截断，文章列表、footer 经常整个消失。根因（一个组件在服务端渲染时返回了 null）**已修复上线并验证**。如果之前看到的是这种"缺内容"，现在刷新就是完整的。

其他页面"内容不见了"的对应解释：友链页/杂谈页空 = 数据库 0 条没录入；小说页/关于页 = 占位页（功能还没做内容方案）；追番页 = 数据写死在前端，改数据要改代码。

## 4. 常见修改指南（改哪里 → 怎么改 → 有什么影响）

> **三条铁律**（改代码前必读，详细原因见交接文档 0.1）：
> ① 前端改动在 `web/` 目录（它是独立 git 仓）：`git add <具体文件>` → commit → `git push origin main` → GitHub Actions 自动部署（约 1.5 分钟）。**改了不 push = 不会上线**。
> ② 后端改动在 `Kirameku-backend/`：需要 SMB 同步到 NAS → docker 重建容器（流程复杂，建议交给 AI 或按交接文档 8.3 节操作）。
> ③ **能在后台改的就不要改代码**（站名/描述/导航/侧栏开关/图片，见 2.3 节）——后台改完 60 秒生效，零风险。

### 4.1 不用改代码就能做的（后台操作）

| 想做的事 | 怎么做 | 影响 |
|:--|:--|:--|
| 发文章 / 改文章 | 后台 → 文章管理 | 前台立即出现；SSE 会通知正在浏览的访客 |
| 换站名 / 描述 / 头像 / Banner 图 | 后台 → 站点配置（见 2.3） | 全站生效，≤60 秒 |
| 加友链 | 后台 → 友链管理 | 友链页立即显示 |
| 删评论 / 审核评论 | 后台 → 评论管理 | 审核通过前访客看不到新评论 |
| 启用音乐挂件 | 后台 → 站点配置 → `music_widget` | 侧栏出现"B 站收藏夹"卡片 |
| 查谁登录过后台 | 后台 → 账号设置 → 安全日志 | — |

### 4.2 需要改前端代码的（改完 `cd web` → add 具体文件 → commit → push main 自动上线）

| 想做的事 | 改哪个文件 | 怎么改 / 影响 |
|:--|:--|:--|
| **改追番页数据** | `web/src/data/anime.ts` | 文件头有注释：往 `animeData` 数组追加 `{title, cover, link, status, rating, progress}`；状态筛选和计数自动生成。cover 不填显示渐变占位。影响：仅追番页 |
| **改侧栏默认编排**（widget 顺序/所在列/停靠位） | `web/src/config/sidebarConfig.ts` | 文件头有完整注释。`components` 数组顺序 = 显示顺序；`slot: "top"|"sticky"`、`column: "primary"|"secondary"`、`pages: [...]` 限定显示页面。影响：全站侧栏（后台 `sidebar_widgets` 开关仍可覆盖单个 widget 的显隐） |
| **改音乐播放器配置**（原 Shirone 播放器，当前关闭） | `web/src/config/musicConfig.ts` | 文件头有四种模式使用指南。⚠️ `enable` 必须保持 `false`——开启会触发 stylus 与 Cloudflare Workers 的运行时冲突（站点会报错）；当前音乐功能由 `MusicLinkCard` 外链卡片替代 |
| **改默认站名/描述**（仅兜底值，后台配置优先） | `web/src/config/siteConfig.ts` | 后台填了 `site_title` 就以后台为准，这里只在后台没配时生效 |
| **改公告栏** | `web/src/config/announcementConfig.ts` | 内容/链接/可关闭时长；也可被后台 `sidebar_widgets` 关掉 |
| **改页脚** | `web/src/config/footerConfig.ts` | 页脚链接、备案号、版权文案 |
| **改作者资料卡** | `web/src/config/profileConfig.ts` | 头像/昵称/简介/社交链接（不填后台 `site_images.avatar` 时用这里的） |
| **改字体** | `web/src/config/fontConfig.ts` | 主字体是 Yozai（已子集化 770KB）。换字体要同时改 `scripts/subset-font.mjs` 的源字体路径，否则 CI 构建会失败 |
| **改文章页功能开关**（分享海报/目录/版权声明等） | `web/src/config/articleConfig.ts` | 各功能 `enable` 开关 |
| **改统计（静态兜底）** | `web/src/config/umamiConfig.ts` | 后台 `umami` 配置优先于这里 |
| **改后台可配项的"解析规则"** | `web/src/utils/site-overrides.ts` | 文件头注释列了全部配置键；新增后台可配项时在此加解析（照 `umami`/`music_widget` 的写法抄） |
| **改小说页 / 关于页内容** | `web/src/pages/novel.astro`、`web/src/pages/about.astro` | 目前是占位壳，直接往里写内容即可（或做成后台可配，交给 AI） |
| **改导航的兜底默认值** | `web/src/utils/navigation-api.ts`（前端取数）＋ 后台 `navigation`（实际数据） | 后台数据优先；这里只影响后台没配时的兜底 |

### 4.3 需要改后端/BFF 的（影响大，建议交 AI 操作）

| 想做的事 | 位置 | 影响 / 流程 |
|:--|:--|:--|
| 改接口/数据模型/评论点赞规则 | `Kirameku-backend/app/`（每个文件头部有注释） | 改完要走：SMB 同步 → NAS docker build → 重建容器（交接文档 8.3 全流程）；有表结构变更必须先跑数据库迁移 |
| 改缓存时间/失效策略 | `worker-bff/src/index.ts`（读接口默认 60s+SWR 300s） | 改完 `cd worker-bff && ./scripts/Deploy.ps1` 部署。调小=内容更新更快但回源更频繁 |
| 管理后台界面 | `Kirameku-backend/admin/src/views/`（每个目录一个功能页） | 改完要 build + 同步 dist 到 NAS + restart 容器（详见交接文档 8.3 第 5 步，**必须 restart 否则后台 404**） |

### 4.4 影响对照速记

- 改 `web/src/config/**` → 只影响对应页面/组件，风险低，push 即上线。
- 改 `web/src/components/**` → 小心：island 组件（`src/components/islands/`）在服务端渲染时**绝对不能 return null**，否则整个页面会被截断（09-13 刚修过一次这种事故，见坑 6.1.14）。
- 改后端 → 影响所有前台数据，改错会导致前台取不到数；动手前先看交接文档第 6 节的坑。
